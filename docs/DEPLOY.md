# Deploying

The site is a static Next.js app with one dynamic route (the waitlist endpoint).
Vercel is the intended host; nothing here is Vercel-specific except the
`x-vercel-ip-country` header the waitlist reads, which degrades to `null`
elsewhere.

## First deploy

1. Import the repository into Vercel. The framework preset, build command and
   output directory are all detected — no overrides.
2. Set the environment variables below.
3. Point `tryplumi.app` at the deployment, and set `plumi.study` to redirect to
   it. The site declares `tryplumi.app` as its canonical domain in
   `src/config/site.ts`; serving the same pages on both without a redirect
   splits the SEO between them.

## Environment variables

| Variable | Environment | Required | Notes |
|---|---|---|---|
| `SUPABASE_URL` | Production, Preview | For signups | Server-side only |
| `SUPABASE_SERVICE_ROLE_KEY` | Production, Preview | For signups | **Must not** be prefixed `NEXT_PUBLIC_` — see `WAITLIST.md` |
| `SUPABASE_WAITLIST_TABLE` | — | No | Defaults to `waitlist_signups` |
| `NEXT_PUBLIC_POSTHOG_KEY` | Production | For analytics | Without it, analytics is inert |
| `NEXT_PUBLIC_POSTHOG_HOST` | Production | No | Defaults to the EU cloud |

Consider leaving `NEXT_PUBLIC_POSTHOG_KEY` **unset on Preview** so that
deploy-preview traffic and the team's own clicking do not enter the funnel.

## Before going live

- [ ] Waitlist configured and tested end to end — submit a real address and see
      the row appear. Until this is done the form shows an honest error, which
      is correct behaviour but is not a launch state.
- [ ] `TODO(founder):` lines resolved in `/privacy` and `/terms`. There are
      four: the legal entity and registered address (twice), the ICO
      registration, and the Supabase region. They render visibly on the page
      on purpose.
- [ ] `hello@tryplumi.app` actually receives mail. It is the only contact route
      on the site and it is in the footer, the privacy page and the terms.
- [ ] Social preview checked in a real client. `public/og.png` is generated by
      `npm run og`; re-run it if the headline changes.

## On launch day

One change, in `src/config/site.ts`:

```ts
export const launchMode: LaunchMode = "appStore";
export const appStoreUrl: string | null = "https://apps.apple.com/gb/app/plumi/id…";
```

Then redeploy. Every call to action switches label, destination and analytics
event together. The build fails if you flip the mode without setting the URL.

Worth doing at the same time, though neither is required:

- Send the waitlist the launch email before the site changes, not after. The
  page will stop saying "join the waitlist" the moment it deploys, and a
  student who arrives from that email to a Download button they were not
  expecting has had their place in the queue quietly deleted.
- Revisit the FAQ. "When does it launch?" and "Is it free?" both answer as a
  pre-launch product; the first becomes wrong and the second needs the price
  that will by then exist.

## What the site does not need

No database for page rendering, no CMS, no image CDN beyond Vercel's own, no
edge config, no feature-flag service. Landing variants are a query parameter
(`?v=notebook` / `?v=decide` / `?v=mirror`) resolved at render time. Copy is in
`src/content/` and ships with the deploy.
